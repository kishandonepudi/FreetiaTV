## 3. Features missing that block store release
- **No add/edit playlist screen.** The `store` flavor ships without a playlist, so that build can't do anything.
- No Settings screen, so no "Exit app" or "Clear cache" there, and no way to turn Child Safe Mode on.
- Still unbuilt: search, favourites, PIN/lock UI, EPG, reminders, sleep-timer UI, and the audio, caption and quality menus.
- The channel list loads the whole playlist into memory. Large playlists (10,000+ channels) need paging.
- Playlist URLs are stored in plain Room tables, not encrypted storage as spec §5 requires.

## 4. Code problems likely to fail store review
- **The app opens itself on every boot.** [BootReceiver.kt](app/src/main/kotlin/com/freetia/tv/receiver/BootReceiver.kt) never checks the `AUTO_START_ON_TV` setting, which the spec says is off by default. Users won't expect this and reviewers flag it.
- **Background playback is declared but not used.** `PlaybackService` is exported and `FOREGROUND_SERVICE_MEDIA_PLAYBACK` is declared, but the UI plays inside the activity. Play makes you justify that permission on API 34+, so either connect it or remove it for 1.0.
- **Notifications won't show on Android 13+.** `POST_NOTIFICATIONS` is declared but the app never asks for it at runtime.
- **Database schema isn't exported yet.** Room is set to export it, but no `app/schemas/` folder exists. Commit it after the first build so later versions can migrate.
- **The ProGuard rules have leftover entries.** They keep Moshi classes (Moshi isn't a dependency) and all of `androidx.media3`. The release build will work, just bigger than it needs to be.

- There are only 3 unit tests, all in [M3uParserTest.kt](app/src/test/kotlin/com/freetia/tv/data/parser/M3uParserTest.kt).
- No tests yet for:

  - `EncryptionManager`
  - the database queries
  - anything on a device or in the UI
